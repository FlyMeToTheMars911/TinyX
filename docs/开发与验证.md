# TinyX 0.1.0 开发与验证

## 本次实现

| 项目 | 行为 |
| --- | --- |
| 桌面窗口 | C# / WinForms，默认约 400 × 600，主屏工作区左下角；无标题栏和浏览器工具栏 |
| 操作 | 默认置顶，可通过托盘切换；Ctrl + Alt + X 全局显隐；托盘恢复、移动、刷新、完整网页模式和退出 |
| 尺寸与位置 | 四边调整大小；Alt 拖动顶部细边缘；保存逻辑尺寸和相对工作区位置，恢复时限制在可见工作区 |
| 推文模式 | 注入本地 CSS / JS，隐藏导航、推荐和浮层，主列铺满；保留详情、互动、媒体与认证表单 |
| 资源策略 | 单 WebView；无轮询、无自动刷新；禁止视频自动播放，允许手动播放；隐藏先完成原生操作，再暂停视频、尝试挂起或设置低内存目标 |
| 稳定性 | 全局热键冲突提示、单实例唤醒、隐藏操作不依赖网页脚本成功、异常尺寸配置归一化 |
| 用户数据 | 独立本地 WebView2 目录；限量日志不含 Cookie、令牌、推文正文或完整网址；不读取 Chrome 凭证 |
| 交付 | 框架依赖 Windows ZIP、可选包含 .NET 的包、锁定 NuGet 依赖、GitHub 构建工作流 |

第一次本地模拟页面测试发现 `NavigateToString` 在导航事件中使用 `data:text/html` 地址；已修复为仅在显式本地测试模式允许首次本地 HTML 导航，并重新运行通过。正常使用仍禁止顶层 `data:`、`file:`、`javascript:` 导航。

网页脚本测试不依赖第三方包；集成诊断文件只包含布尔状态、数量和进程内存，保存在本地，不纳入公开仓库。

## 内存口径

一次短时离线模拟页面快照中，宿主私有提交内存约 46 MiB，宿主与 WebView2 全进程组约 225 MiB。隐藏后约 235 MiB，未在该短时间内观察到下降。X 网页初始导航阶段的进程组私有提交约 335 MiB，页面仍在加载。这些数字是开发机器上的瞬时快照，不是已登录时间线的稳定基准或最低保证。

`PrivateMemorySize64` 是私有提交内存，不能当作物理常驻内存；各进程工作集相加可能重复计算共享页。挂起减少后台活动、允许运行时调整资源，不保证立即返还所有内存。没有采用禁用 GPU、周期性强制 GC、清除登录数据等方式制造较低读数。

## 已知边界

- Chrome 已登录与 TinyX 已登录互不等价。TinyX 不复制 Chrome Cookie 或密码。
- 现有 Chrome 配置的自动启动测试被环境自动审批拒绝，返回仅为 `blocked by policy`；没有重试该操作。
- X 改版可能影响 CSS / DOM 选择器；完整网页模式始终可通过托盘恢复。
- Google / Apple 登录受身份提供商对嵌入式浏览器的限制，不能保证可用；应实测 X 自身登录流程。
- 程序未签名，下载后 Windows 可能显示来源提示。WebView2 Runtime 和 .NET 运行时分别适用其自身许可。
